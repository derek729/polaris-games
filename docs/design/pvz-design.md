## 1. 목표

현재 게임은 "해바라기 → 완두 앞라인" 단일 정답 반복에, 웨이브가 정해진 시간표(`WAVES`)대로만 진행되어 **다가올 위협을 읽고 대비하는 레인 판독 재미**가 없고, 좀비가 전부 "걸어와서 먹기"만 해 방어 해법이 한 가지로 수렴한다. 또한 플레이어의 개입점이 배치/수확뿐이라 위기 상황에서 할 수 있는 능동적 반격(클러치)이 존재하지 않는다. 본 문서는 ①위협 예고(텔레그래핑) ②새 적 유형 ③한 발 클러치 스킬의 3축으로 "읽기 → 대비 → 반격" 루프를 완성하는 것을 목표로 한다.

## 2. 개선 항목 (우선순위 순)

### 2.1 [P1] 웨이브 예고 + 장비 파손 3단계 텔레그래핑 — 규모 **M**

#### 배경 (리서치 근거)
- 브리프 (1)-4 "가시적 성취 + 텔레그래핑", (4)-1 "웨이브 예고 시스템 — 가장 싼 텐션 부스트", (4)-2 "피해 누적별 시각 파손 3단계 + 등장 시 실루엣 미리보기".
- 코드 검증: 웨이브 알림은 `update()`의 웨이브 루프에서 **생성 시점에만** `banner("웨이브 N")`이 뜨고 사전 정보는 전혀 없음. 콘/버킷 장비는 `drawZombie()`에서 `z.hp > ZTYPES.normal.hp`(190)일 때만 그려지는 **이진 상태**(장비 온전 ↔ 소실)라 피해 누적 피드백이 없음. 반면 `wallnut` 드로잉은 이미 `ratio < 0.66 / < 0.33` 3단계 균열 패턴이 자사 표준으로 존재 → 동일 패턴 확장.
- 수치 기준은 코드 값 사용(cone 560 / bucket 1250). 브리프의 원작 수치(570/1300)와 다르므로 본 문서가 우선한다.

#### 명세

**A. 다음 웨이브 미리보기 (진행바 아래)**
- HUD 진행바(`bx=690, by=25, bw=236, bh=16`) 아래 행 **y 48~66** 에 다음 웨이브(`WAVES[game.waveIdx]`, 마지막 웨이브 이후엔 비표시) 조성을 표시.
- 표기: 타입별 아이콘 1개 + `×N` (표시 순서: flag → bucket → thrower → cone → runner → normal). 아이콘은 `drawZombie()` 폴백 머리 드로잉(피부 원 14px + 장비 형태)을 축소 재사용 — PNG 유무와 무관하게 동일 렌더.
- 대량 웨이브(`w.z.length >= 6`)는 행 배경에 붉은 반투명 띠 + 우측에 "대규모!" 11px 라벨.
- 기존 "웨이브 N / M" 텍스트(현재 y=63 중앙)는 같은 행 우측정렬(x=926)로 이동.

**B. 최종 웨이브 사전 경고**
- `game.time >= FINAL_T - 15` 도달 시 1회: `banner("🚩 대량 좀비 다가온다! 방어 준비", "#ff5252", 30, 2.5, 290)` + 신규 사운드 `SFX.warn = () => tone(700, 180, 0.4, "sawtooth", 0.3)` (파일 훅: `playSfx("warn", {volume: 0.4})`) + 진행바 우측 🚩 아이콘 알파 깜빡임(`sin`).
- 중복 발동 방지 플래그 `game.finalWarned`(기본 false) — `newGame()`에서 초기화.

**C. 장비 파손 3단계 (cone / bucket)**
- 계산: `armorRatio = (hp - 190) / (ZTYPES[type].hp - 190)` (190 = `ZTYPES.normal.hp`, 장비 소실 경계 유지).

| 단계 | cone (hp 560) | bucket (hp 1250) | 시각 (오버레이) |
|---|---|---|---|
| 1단계 (ratio > 0.6) | hp > 410 | hp > 825 | 정상 (현행) |
| 2단계 (0.25~0.6) | hp 280~410 | hp 455~825 | 콘: 상단 꺾임 + 금 1줄 / 버킷: 측면 찌그러짐 곡선 1줄, 광택선 제거 |
| 3단계 (ratio < 0.25) | hp < 280 | hp < 455 | 콘: 뾰족 절단 + 금 2줄 / 버킷: 구멍 1개 + 8° 기울임 |
| 소실 (기존 유지) | hp ≤ 190 | hp ≤ 190 | 장비 미표시 (현행 동작 보존) |

- **오버레이 방식**: 금/구멍/기울임은 캔버스 스트로크로 **PNG 스프라이트 위에도 동일 적용**(기존 얼림 `❄` 오버레이와 같은 패턴) → 스프라이트 교체 없이 폴백/PNG 양쪽에서 단계 표현.

#### 구현 포인트
- `update()` 웨이브 루프(주석 "웨이브 진행") 직후에 `finalWarned` 체크 추가.
- `drawHUD()`의 "웨이브 진행 바" 블록 아래에 미리보기 행 렌더 추가 (좌표 여백 확인됨: 씨앗 패킷 열은 x ≤ 582, 삽은 x ≤ 670 → x 690~926 구간 비어 있음).
- `drawZombie()`의 `z.type === "cone"` / `"bucket"` 장비 분기에 `armorRatio` 단계 계산 후 분기 드로잉; PNG 경로(`drawImage` 후 return 직전)에도 오버레이 호출 추가.
- `newGame()`에 `finalWarned: false` 추가. `SFX` 객체에 `warn` 추가.

#### 수용 기준
- [ ] 진행바 아래에 항상 "다음 웨이브" 좀비 구성(타입별 개수)이 보인다. 첫 웨이브(t=20) 전에도 포함.
- [ ] 최종 웨이브 15초 전 경고 배너 + 경고음이 정확히 1회만 재생된다.
- [ ] 콘/버킷 좀비가 피해 누적에 따라 외형이 3단계로 변하고, hp 190 이하에서 장비가 사라지는 기존 동작은 유지된다.
- [ ] `game-assets/pvz/*.png` 스프라이트가 있는 환경과 없는 환경(폴백) 모두에서 단계 표시가 동작한다.
- [ ] 미리보기/경고 UI가 씨앗 패킷·삽·버튼과 겹치지 않는다.

#### 규모: **M**

### 2.2 [P2] 신규 좀비 2종 — 화병 투척형(thrower) · 질주형(runner) — 규모 **L**

#### 배경 (리서치 근거)
- 브리프 (4)-4 "적 2~3종 추가: 투척형(식물 직접 공격), 빠른 러너", (2) "새 적은 소량 섞어 가르친 뒤 본격 투입", (1)-2 "레인 압력 읽기".
- 코드 검증: 모든 좀비가 `Zombie.update()`의 단일 근접 로직(식물 접촉 → `62/s` 먹기)만 사용. 원거리 위협이 없어 "호두 앞벽 + 뒤 완두" 고정 해법이 최적. 투척형은 벽 뒤 초점 공격으로 배치를 강제하고, 러너는 레인 판독·대응 속도를 압박한다.

#### 명세

**신규 데이터 (`ZTYPES` 확장)**

| 항목 | thrower (화병 투척형) | runner (질주형) | 비교: normal |
|---|---|---|---|
| hp | 340 (완두 17발) | 160 (완두 8발) | 190 |
| spd (px/s) | 12 | **46** (일반의 약 2.9배) | 16 |
| 공격 | 사거리 260px 내 정지 후 **2.2초마다 화병 투척, 화병 1발 = 40 고정 피해** | 근접 62/s (기존 공용 로직) | 근접 62/s |
| 얼림(slowT) | 이동·투척 간격 모두 ×0.45 (기존 `mul` 로직) | 이동 ×0.45 | 동일 |
| 첫 등장 | 웨이브 5 (1마리 — 가르치기) | 웨이브 3 (1마리 — 가르치기) | — |
| 스프라이트 계약 | `game-assets/pvz/zombie-thrower.png` | `game-assets/pvz/zombie-runner.png` | `zombie-basic.png` |

- **투척 규칙**: 같은 행에서 `pl.cx < this.x`이고 거리 ≤ 260(2.5칸)인 식물 중 가장 가까운(가장 오른쪽) 식물이 대상 → 이동 정지 후 투척. 대상 없으면 계속 보행(느린 일반 좀비처럼). `cherry`는 대상 제외(자폭 식물). 화병은 같은 행 직선 비행(속도 240px/s, 우→좌)이며 **경로상 첫 식물(=가장 오른쪽 식물)**에 명중 → 호두가 화병 탱커로 유효(2400hp ≈ 화병 60발).
- **디자인 의도**: thrower는 화력을 분산시키는 고정 포탑(죽여야 함), runner는 hp를 normal보다 낮게 잡아 "빨리 오지만 잘 죽는" 압박+잔디깎이 유도형으로 상호 다른 레인 압력을 만든다.

**웨이브 테이블 교체 (`WAVES` — 10웨이브 구조 유지, 신규 적은 가르치고 시험)**

| 웨이브 | t | 구성 | 비고 |
|---|---|---|---|
| 1 | 20 | normal | |
| 2 | 50 | normal, normal | |
| 3 | 80 | normal, **runner** | 러너 첫 등장 (교육) |
| 4 | 110 | cone, normal, normal | |
| 5 | 140 | **thrower**, cone, normal | 투척형 첫 등장 (교육) |
| 6 | 170 | bucket, **thrower**, cone, normal | |
| 7 | 200 | **runner, runner**, bucket, cone, normal | 러너 시험 |
| 8 | 230 | bucket, bucket, **thrower**, cone, normal, normal | |
| 9 | 258 | bucket, **thrower, thrower**, cone, cone, **runner**, normal | 복합 시험 (대량 미리보기 대상) |
| 10 | 285 (final) | flag, bucket, bucket, **thrower, thrower**, cone, cone, **runner, runner**, normal, normal, normal | 최종 (총 HP +13%) |

- 총 좀비 수 43 → 45, 최종 웨이브 총 HP 4,770 → 5,390 (+13%). 상쇄 수단으로 2.3의 클러치 스킬을 함께 투입(우선순위 P3가 이 이유).
- `FINAL_T`는 코드가 `WAVES[WAVES.length-1].t`에서 자동 파생하므로 **데이터 교체만으로 완결**. 승리 체크도 `WAVES` 제네릭 루프라 코드 변경 불필요.

**렌더링/사운드**
- **스프라이트 파이프라인 계약 재사용 (선택 명시)**: `SPRITES` 배열에 `"zombie-thrower"`, `"zombie-runner"` 추가 + `ZSPRITE` 맵 등록. 파일 부재 시 기존과 동일하게 폴백 캔버스 드로잉으로 그린다 — **폴백 드로잉은 필수 구현**.
  - thrower 폴백: 기본 좀비 몸 + 왼손에 갈색 화병(원 + 입구 타원) + 목에 붉은 스카프.
  - runner 폴백: 기본 좀비 몸을 앞으로 10° 기울임 + 머리에 띠 1줄 + 머리 옆 땀 방울 2개, 다리 스윙 진폭 ×1.6.
- 사운드: `SFX.throw = () => tone(300, 120, 0.12, "triangle", 0.15)` + `playSfx("throw")` 훅. 화병 명중은 기존 `playSfx("hit", {volume: 0.35, throttle: 300})` 재사용.

#### 구현 포인트
- `ZTYPES`에 `thrower: { hp: 340, spd: 12 }`, `runner: { hp: 160, spd: 46 }` 추가.
- `Zombie` 생성자에 `this.thrT = rand(0.8, 1.6)` 초기화. `Zombie.update()`에서 `type === "thrower"` 분기: 대상 탐색(plantAt 루프 재사용) → 정지 + `thrT` 카운트(`mul` 곱) → 발사.
- 화병은 **`Pea` 클래스에 `evil` 옵션 추가**로 재사용(새 배열 불필요): `evil=true`면 `vel = -240`, 충돌 대상이 좀비가 아닌 `game.plants`(같은 행, x 범위 반전), 명중 시 `target.hp -= 40; target.flashT = 0.15`, `draw()`에서 갈색 렌더. 기존 호출부는 시그니처 호환.
- `drawZombie()`에 신규 폴백 케이스 2종 추가(위 명세). `SPRITES`/`ZSPRITE` 등록.
- `WAVES` 배열 교체.
- 주의: `drawZombie` 장비 조건(`z.hp > ZTYPES.normal.hp`)은 신규 좀비에 적용되지 않게 타입 가드 유지(신규 좀비는 장비 없음).

#### 수용 기준
- [ ] thrower가 식물과 2.5칸 이내 접근 시 정지하고 2.2초 간격으로 화병을 던지며, 맞은 식물이 40 피해를 받는다.
- [ ] runner 속도가 normal의 약 3배이고 완두 8발에 사망한다.
- [ ] runner는 3웨이브, thrower는 5웨이브에서 각 1마리로 처음 등장한다(웨이브 미리보기에서도 동일하게 보임 — 2.1 연동).
- [ ] 두 좀비 모두 PNG 없이 폴백 드로잉만으로 기존 좀비와 육안 구분된다.
- [ ] 얼음 완두에 맞으면 이동/투척이 모두 둔해진다.
- [ ] `WAVES` 데이터 교체만으로 10웨이브 승리 조건이 기존 코드와 동일하게 동작한다.

#### 규모: **L**

### 2.3 [P3] 클러치 버스트 스킬 "태양 광폭" (Plant Food형) — 규모 **M**

#### 배경 (리서치 근거)
- 브리프 (3) "PvZ 2 Plant Food — 클러치 카운터플레이", (4)-10 "Plant Food식 클러치 스킬: 전체 화력 버스트(쿨다운 1회)", (3) Kingdom Rush/Bloons의 능동 스킬 개입점.
- 코드 검증: 플레이어 개입은 배치/수확뿐. 2.2로 후반 압박이 오르므로, 이를 상쇄하는 1회성 반격 카드가 필요. 태양 **수집 행위**를 충전 조건으로 하면 기존 경제(선 소비)를 왜곡하지 않고 활동성을 보상한다.

#### 명세

| 항목 | 값 |
|---|---|
| 버튼 위치 | HUD 빈 영역 **(x=690, y=72, w=236, h=44)** — 2.1 미리보기 행(y 48~66)과 수직 분할, HUD 하단(130px) 내 |
| 단축키 | `Q` (기존 1~6 = 식물 선택과 병존) |
| 충전 | 태양 **12회 수집** = 1충전, **최대 1개 저장** (넘는 수집은 낭비 — 재는 리셋) |
| 효과 1 | 모든 슈터(peashooter/snowpea/repeater) 즉시 3연발 발사 (repeater는 6발). pea는 각각 x 오프셋 -18/0/+18로 push |
| 효과 2 | 전체 좀비에게 즉시 **80 고정 피해** + `flashT = 0.3` (사망 시 기존 `killZombie` 경유) |
| 효과 3 | 연출: 골드 배너 `banner("⚡ 태양 광폭!", "#ffd23e", 40, 1.6, 290)` + `shake = 8` + 좌우 화면 플래시(알파 0.25, 0.3s) |
| 예외 | 투척체의 화병에는 무효(좀비만 대상), runner 포함 전 좀비 대상. 일시정지/메뉴 상태에서는 발동 불가 |
| 밸런스 근거 | 평균 5레인 × 슈터 2기 = pea 10발(200dmg) + 전체 80 → 체리폭탄(1800/150선)보다 약하지만 전 레인 커버. 게임당 예상 충전 ~4~5회(285초 기준) |
