## 0. 범위와 하드 제약

1. **게임 9종 HTML 전면 교체는 이번에 하지 않는다.** 폰트·팔레트가 게임별로 다르게 새겨진 상태에서 일괄 교체는 파손 리스크가 크다. 원칙은 **"신규·수정 코드는 토큰 사용"** + **로비(`index.html`)만 이번 사이클에 완전 적용**한다. 나머지 8종은 토큰 없이도 현재와 동일하게 동작해야 한다(무영향 검증 포함).
2. **design-tokens.css는 순수 CSS 변수 파일이다.** 셀렉터 0개, 컴포넌트 0개 — 레이아웃/컴포넌트는 제공하지 않는다(NES.css의 "CSS Only, layout은 사용자 정의" 원칙 동일, §2). 게임 페이지가 파일 1줄 링크로만 채택할 수 있게 한다.
3. **서버 없음·file:// 동작 병행**(기존 Phase 1·2 제약 계승). 토큰 파일은 상대경로 링크로 동작해야 하고, 빌드 과정이 없으므로 단일 정적 CSS로 끝난다.
4. **기존 아트 파이프라인 하위호환.** `generate_sprite.py` 프리셋 확장 후에도 `--preset` 생략 시 기존 동작(1024 스프라이트 생성)과 동일해야 한다. 기존 PNG 33종은 art-lint day-1 전수 통과 규격으로 설계한다(§6-4).
5. **아트 도구는 저장소 밖(`~/comfyui`), 검증 도구는 저장소 안.** 생성 스크립트는 ComfyUI 의존(GPU 12GB), art-lint는 Pillow만 의존해 개발·QA 누구나 CLI로 돌릴 수 있게 한다.
6. **색 변경은 로비 액센트 1곳만.** 로비 액센트를 바이올렛 `#7c6cff` → 도토리 골드로 전환한다(브랜드 톤 반영). 이외 색은 현재값 그대로 토큰화한다 — "디자인 강화"의 1차 목표는 새 그림이 아니라 **흩어진 값의 수렴과 검증 자동화**다.

## 3. 산출물 1 — `design-tokens.css` 명세

**위치**: `design-tokens.css`(저장소 루트 — `index.html`·각 게임과 동층, 상대경로 링크 1줄로 채택). 신규 파일.

### 3-1. 명명 규약

`--p-{분류}-{단계|역할}` — open-color의 `--oc-(color)-(number)` 규약 준용. 분류 6종: `navy`(표면) · `gold`(브랜드) · `teal|violet|coral`(게임 액센트 3종) · `state`(상태) · `font|space|radius|shadow`(형태).

| `--p-navy-700` | `#1e2440` | 카드 hover | 로비 `--card-hover` |

### 3-3. 폰트 스택 3종

```css
--p-font-ko:      "Galmuri11", "Pretendard", "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif;
--p-font-display: "Press Start 2P", "Galmuri11", monospace;   /* 영문·숫자 디스플레이 — NES.css 권장 구조(§2) */
--p-font-data:    "JetBrains Mono", ui-monospace, "SF Mono", Consolas, monospace;  /* 좌표·점수·로그 */
```

- `--p-font-display`는 라틴 외 문자를 Galmuri11로 폴스루시키는 NES.css 방식이므로 한글 타이틀도 안전.
- `--p-font-data`는 v1에서 **스택 선언만** 하고 폰트 파일 동봉(JetBrains Mono woff2, OFL)은 후속 S 과제로 분리한다 — 현재 suiji 계열의 CDN 의존을 흡수할 준비만 마련.

### 3-4. 간격·반경·그림자

```css
/* 간격 — 4px 기본 격자 */
--p-space-1: 4px;  --p-space-2: 8px;  --p-space-3: 12px; --p-space-4: 16px;
--p-space-5: 24px; --p-space-6: 32px; --p-space-7: 48px; --p-space-8: 64px;
/* 반경 — 레트로 원칙은 0(NES.css), 기존 카드 호환분만 유지 */
--p-radius-0: 0;    --p-radius-1: 4px;  --p-radius-2: 8px;
/* 그림자 — blur 0 하드 픽셀 그림자 (NES.css 버튼·컨테이너 방식) */
--p-shadow-pixel-s: 2px 2px 0 rgba(5, 8, 20, .55);
--p-shadow-pixel-m: 4px 4px 0 rgba(5, 8, 20, .55);
--p-shadow-gold:    0 0 12px rgba(217, 164, 65, .35);  /* 강조 글로우, 예외적 blur 허용 */
```

### 3-5. 레거시 별칭 — 로비 무파산 전환의 핵심

파일 말미에 로비 기존 변수명 8개를 별칭으로 재정의한다:

```css
/* 레거시 별칭 — index.html 인라인 :root 블록 삭제 후 호환. 신규 코드 금지 */
:root {
  --bg: var(--p-navy-900);   --card: var(--p-navy-800); --card-hover: var(--p-navy-700);
  --line: var(--p-navy-600); --text: var(--p-text);     --muted: var(--p-muted);
  --accent: var(--p-gold-500);                          /* ★ 유일한 값 변경: 골드 전환 */
  --accent2: var(--p-teal-400);
}
```

로비의 var( ) 소비 25곳(인라인 스타일 문자열 `polaris-common.js` 계통 포함)은 **수정 0행**으로 토큰을 따라간다. 로비 적용 = `<link rel="stylesheet" href="design-tokens.css">` 1줄 추가(fonts.css 링크 아래) + 인라인 `:root` 블록 8줄 삭제. 전부.

## 4. 산출물 2 — 디자인 가이드 (본 문서 §4가 그 자체다)

`docs/design/디자인시스템-v1.md` — 기획서와 가이드를 한 문서로 유지한다(문서 2중 관리 방지). 구성은 §3(토큰 사용법) + 아래 4-1~4-3.

### 4-1. 에셋 규격 (아트팀 납품 기준 — art-lint가 기계 검증)

| 구분 | 치수 | 배경 | 용량 | 색수 |
|---|---|---|---|---|
| 스프라이트 | 64×64 (보스 128×128) | 투명 | ≤15KB (128px ≤40KB) | ≤256색 |
| 아이콘 | 32×32 | 투명 | ≤8KB | ≤256색 |
| UI(버튼·프레임) | 64 or 96 정사각 | 투명 | ≤15KB | ≤256색 |
| 타일 | 128×128 | 불투명 | ≤40KB | ≤256색 |
| 배경 | 672×384 | 불투명 | ≤120KB | ≤256색 |
| 스토어 커버 | 1200×630 | 불투명 | ≤250KB | ≤256색 |

파일명 컨벤션: `bg-*.png`/`*-background.png`=배경, `cover*.png`=커버, 그 외=스프라이트류(art-lint 규칙 추론 기준, §6-2). atlas는 `atlas*.png`로 검사 제외.

### 4-2. 프롬프트 레시피 (프리셋별 — §5와 1:1 대응)

```
sprite:  pixel art <대상>, <색 2~3 명시>, <시선>, game sprite, transparent background, centered
icon:    pixel art <대상> icon, single object, thick outline, flat colors, centered
ui:      pixel art UI <버튼|프레임>, flat colors, 9-slice friendly, no text
tile:    seamless tileable pixel art <재질> texture, flat, repeating pattern, no vignette, no shadow
background: pixel art <장면> background, wide shot, no text, no characters, dark navy palette
cover:   pixel art <게임명 장면> key visual, bold composition, no text
```

공통 네거티브(기존 유지): `blurry, photo, realistic, 3d render, text, watermark, jpeg artifacts, gradient background, shadow`. 색은 **토큰 팔레트 색상어**(예: `dark navy background, golden accents`)로 지시해 게임과 톤을 맞춘다.

### 4-3. 새 페이지 체크리스트 (개발팀 — PR 전 자가 점검)

1. `<head>`에 `game-assets/fonts/fonts.css` + `design-tokens.css` 링크(상대경로).
2. 폰트는 `var(--p-font-ko|--p-font-display|--p-font-data)` 3스택 중 선택 — 신규 CDN 폰트 로드 금지.

## 6. 산출물 4 — `game-assets/art_lint.py` 자동 검증

**위치**: `game-assets/art_lint.py`(신규, 저장소 안). 의존성 Pillow뿐(present 실측) — pngquant·ComfyUI 불필요. 개발·QA가 **배포 전 실행**.

### 6-1. CLI

```bash
python3 game-assets/art_lint.py                 # game-assets/ 전수, 사람용 목록 출력
python3 game-assets/art_lint.py --json          # CI/에이전트 소비용
python3 game-assets/art_lint.py --root <경로>   # 특정 폴더만
```

종료코드: 위반 0건=0, 1건 이상=1. 출력: `파일경로 | 프리셋 추론 | 위반 항목: 기대값 vs 실측값` 목록 + 요약(N종 검사, M종 위반).

### 6-2. 규칙 추론

`bg-*.png`·`*-background.png`→background 규칙, `cover*.png`→cover 규칙, `atlas*.png`·`*.json`→검사 제외, 그 외→스프라이트류 규칙(§4-1 표가 곧 기대값 테이블).

### 6-3. 검사 5종

1. **치수**: 규격 표 일치 (예: 스프라이트 32/64/128 정사각).
2. **투명도**: 스프라이트류는 투명 픽셀 존재 + **외곽 1px 테두리 투명**(배경제거 확인), tile·bg·cover는 불투명(알파 255 전체).
3. **용량**: 규격 표 상한.
4. **256색**: PNG color type `P` 또는 고유색 ≤256 — postprocess가 pngquant까지 돌리므로 P 모드가 정상.
5. **NEAREST 흔적(경고)**: ① 정수 배율 k(2~16)의 k×k 균일 블록 전체 일치 → 업스케일 흔적 ② 알파 반톤(0/255 제외) 비율 >5% → 부드운 가장자리(바이리니어·rembg 과다). 경고는 exit 0, 치명 위반만 exit 1.

### 6-4. day-1 통과 설계 (§1-3 실측)

기존 33종은 전부 P 모드·32/64/128px·최대 7KB·투명 배경 → **초기 전수 통과**가 보장되는 규격이다. 즉 art-lint 도입으로 잡히는 것은 "앞으로의 위반"이지 기존 자산 재작업이 아니다.
