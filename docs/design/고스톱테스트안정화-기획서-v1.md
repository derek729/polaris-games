## 1. 목표

간헐 실패의 실체를 규명하고 그 아래 가려져 있던 **실제 게임 로직 버그 2건**을
수리한다: ① 섯다 2~7땡 등급 반전 ② 섯다 덱 40장 중복 구성(실게임 판 영향).
+ raw assert 실패가 카운트되지 않는 테스트 위생 문제 수리.

## 2. 명세

### 2-1. 진단 방법 (기록 — 재사용 가능한 절차)
1. 시드 고정 루프(diag): 덱 셔플 글로벌 RNG(seed(s)) + 에이전트 rng.seed 동시
   고정 → 단일 게임 500시드 = **0 실패**(엔진 무결성 입증).
2. 스위트 문맥 재현(diag 2차): 공용 에이전트·RNG 오프셋 흉내 = 0 재현 →
   스위트 계층 의심.
3. 전체 스위트 반복 실행 + 임시 계측(DEBUG77)으로 실패 1회 포획 → **결함은
   AI 시뮬이 아니라 결정론 테스트 2종**(뻑 스택·섯다 랭킹)에서 발생.

### 2-2. 수리 1: 섯다 땡 등급 공식 반전 (sutda_ranking.gd)
- 실측: _ttaeng_grade가 `TTAENG_8 - (8 - month)` → 2땡=24(=ALI 충돌)·3땡=25…
  7땡=29 — 2~7땡이 특수족보·끗 등급대와 겹치고 순위 역전.
- 수리: `TTAENG_8 + (8 - month)` → 2땡=36…7땡=31, enum 정의와 정확 정렬.
  검증: 집중 스크립트로 2~8땡 전부 OK + 순위 체인 10>9>1>2>8 OK.
- 게임 영향: sutda_ai가 grade로 판단 — 2~7땡 보유 시 잘못된 베팅 강도.

### 2-3. 수리 2: 섯다 덱 40장 중복 (sutda_ranking.gd build_deck_months)
- 실측: 월별 4장(중복) — fallback 2장 확보 후 남은 우선순위 패스를 계속 도니
  중복 추가. **SutdaEngine.start_round가 이 덱으로 실제 판을 열어** 같은 카드가
  두 장 나올 수 있던 실게임 버그.
- 수리: fallback 후 break 1줄. 검증: 스위트 덱 섹션 20장·월별 2장 PASS.

### 2-4. 수리 3: 테스트 위생 — raw assert 마스킹 제거
- 원인 발견: GDScript 내장 assert() 실패는 함수 중단만 할 뿐 _tests_failed가
  올라가지 않음 — test_sutda_ranking의 raw assert 3건(땡 순위 등)이 실패해도
  "0 failed"로 보고됨(수주간 마스킹). 덱·땡 버그가 이 아래 가려져 있었음.
- 수리: assert_true 헬퍼 신설(카운티드) + test_sutda_ranking raw assert 3건
  전환. 임시 계측(DEBUG77) 제거.
- **노출 결과**: 마스킹 제거 직후 11 failed 결정론 노출(덱 버그) → 수리 후
  0 failed 기본. 잔여 간헐: nagari redeal 시나리오 5어설션(랜덤 딜 의존)·
  bbuk stack(드문 Got:5) — **이월**(시나리오 테스트의 상태 강제·시드 고정
  정비, 별도 사이클).
