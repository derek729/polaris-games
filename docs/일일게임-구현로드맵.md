## 0. 파이프라인 (매일 반복)

1. **선정** — **온라인에서 잘 나가는(트렌딩) 게임**을 2개 이상 선택한다.
   트렌딩 근거(Poki·CrazyGames 트렌딩, 검색 결과 URL)를 반드시 기록에 남긴다.
   대상은 브라우저에서 플레이 가능한 HTML5 게임으로 한정한다. 대기 목록이
   4개 미만이 되면 새 후보를 추가한다.
2. **REA 라이브 분석** — 게임 페이지를 실제로 띄워 번들을 캡처·정적 분석한다.
   ```bash
   google-chrome --headless=new --no-sandbox --remote-debugging-port=9222 \
     --user-data-dir=/tmp/chrome-rea "<게임 URL>" &   # 대기 6초
   rea list-browser-targets http://127.0.0.1:9222     # endpoint는 URL 형식 필수
   rea analyze-web-bundle http://127.0.0.1:9222 <targetId> --observation-ms 12000
   ```
   실패 시(임베드·SPA 제약) `capture-web-screenshot` + 실관찰로 대체한다.
   엔진 종류·모듈 구조·메커니즘(스폰 규칙·점수 공식·난이도 곡선·판정 로직)을
   추출하고 evidence_id를 기록한다. 분석 후 Chrome은 반드시 종료한다.
3. **자체 구현** — **`/mnt/data/work/games/<슬러그>/index.html`** 단일 파일로
   처음부터 재구현한다(한국어 UI, 다크 테마 #0d1021·골드 #e8b64c·청록 #4fd1c5,
   localStorage 최고기록, 키보드+터치, `#selftest` 검증 모드 — 시드는 mulberry32).
   **원작의 코드·에셋을 복사하지 않는다** — 규칙과 설계만 참조한다. IP 캐릭터가
   있는 게임은 이름·캐릭터도 바꾼다.
4. **등록** — `/mnt/data/work/games/index.html`(게임 셸프)에 카드 추가,
   `/mnt/data/work/games/README.md` 진행 기록 갱신.
5. **검증** — `cd /mnt/work/games && python3 -m http.server 8942` +
   Chrome headless `#selftest` 스크린샷으로 SELFTEST PASS·레이아웃 확인.
6. **기록** — games 저장소에 커밋 `feat: <게임명> (D#N)`. 메인 repo 커밋은
   이 규칙 문서를 바꿀 때만 낸다.
