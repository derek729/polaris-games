## 2. 개발 방향 결정

### 결론: 웹(Three.js) 기반 1:1 결투 액션으로 먼저 검증한다

이유:
1. **이 저장소의 강점과 일치** — 두마당·뱀파이어 키우기 등 단일 파일 HTML 게임
   파이프라인이 이미 검증됨(배포·계정·랭킹 서버까지 구축 상태).
2. **에셋의 즉시 활용 가능 영역이 텍스처** — 모델은 UE 전용이라 웹에 못 쓰지만,
   Infinity Blade의 정체성(어두운 판타지 질감)은 텍스처+라이팅으로 재현 가능.
3. **Infinity Blade의 본질은 그래픽이 아니라 '타이밍 결투' 게임플레이** —
   회피·방어·패리 판정 루프를 먼저 재미로 만들어야 상업 가치가 결정된다.
4. 검증 후 흥행 시 UE5 네이티브로 전환하는 두 단계 전략 (6장).

### 장르 정의

- **한 줄 정의**: "Infinity Blade의 1:1 결투 루프를 키보드 타이밍 액션으로 —
  죽어도 끝나지 않는, 혈통이 이어지는 성 등반."
- 플랫폼: 웹(데스크톱 우선, 모바일 터치 버튼 지원) → 추후 PC/모바일 패키징
- 세션: 1판 3~5분, 런(성 등반 1회) 15~20분
- 핵심 키워드: 판정 액션 / 손맛 / 세대교체 서사 / 짧은 런

## 3. 코어 게임플레이 (v0.3 — 실시간 액션 RPG, 2026-09-26 전환)

초기 프로토타입의 교대식(턴제적) 결투를 **실시간 ARPG 전투**로 전환했다.

```
자유 이동(WASD)으로 거리 조절 ──▶ 근접 진입 시 공격 3연격 ──▶ 적은 가드·회피로 대응
        ▲                                                        │
        │            적 AI: 추적 → 텔레그래프(모으기) → 타격 → 쿨다운
        └── 텔레그래프를 읽어 구르기(무적)·방어·패리로 대응 ◀──────┘
```

- **이동**: WASD/방향키 실시간 이동, 아레나 경계 클램프, 캐릭터 간 겹침 방지.
- **공격**: 언제든 가능(3연격 콤보, 앞으로 러지). 사거리(2.8m) 밖이면 빗나감.
- **적 가드**: 플레이어가 공격하면 확률적으로 적이 방어 — 가드 중 피해 85% 감소,
  가드 게이지가 0이 되면 **가드 파괴**(3초 무방비).
- **패리**: 적 타격 0.26초 이내 방어 시 성공 — 슬로모션 + 적 경직 2.2초(무료 딜타임).
- **회피 구르기**: 0.42초 무적 판정. 적의 "모으기" 텔레그래프를 읽는 것이 핵심.
- **궁극기**: FURY 100% 시 「잉걸불 일섬」 3연속 강타.
- **적 AI**: 추적(러닝 애니) → 사거리 진입 시 공격 → 쿨다운, 스테이지별 속도·
  가드 성향·패턴 풀(상단/좌우/찌르기/연속) 차별화, 최종 보스 2페이즈.

### 성장·진행 — RPG 레이어 (§3.5 참조)

- EXP/레벨 3택 카드, 골드·성 입구 상점, **세대 계승**(사망 시 강화·레벨 유지,
  골드 절반) — 죽어도 메타 진행이 남는 로그라이크식 루프.

## 3.5 룬 성장 — 엘든 링식 순환 (2026-09-26 v0.4, 구현 완료)

진행 화폐를 **룬**으로 일원화하고, 성장·죽음·회복을 소울스러운 순환으로
묶었다.

- **룬**: 잡몹·보스·보물상자가 룬을 떨어뜨린다. 룬 = 경험치+화폐 일체.
- **영지(입구 빛 기둥)**: 가까이 가서 E키 → 완전 회복 + 레벨업(룬 소모) +
  능력치 배분 — **체력/근력/지구력/집중** 4스탯 중 플레이어가 직접 선택
  (빌드 다양화). 상인 구매도 룬으로.
- **스태미나**: 공격 18·구르기 25·방어 피격 12 소모, 지구력 스탯으로
  상한 증가. 리소스 관리가 전투의 뼈대.
- **사망 = 룬 드롭**: 죽으면 보유 룬 전량이 죽은 자리에 붉은 표식으로
  남는다. **세대교체 후에도 표식은 유지** — 다음 세대가 회수하면 전량
  반환(회수 전 재사망 시 소실). 세대교체 서사와 룬 순환이 결합된 핵심 루프.
- 능력치는 세대를 건너 계승된다(빌드 성장은 영구, 룬만 위험).

## 4. 시나리오

### 세계관

신들이 벼려낸 검 한 자루 — **인피니티 블레이드** — 는 그것을 쥔 자에게
불멸을 주는 대신, 그 영혼을 잉걸불로 태워 없앤다. 불멸왕 **아우사르**는
이 검으로 백 년을 군림했고, 이제 자신의 말로를 두려워해 검을 성 최심부에
봉인했다. 검을 다시 꺼내려는 자마다 성의 문지기들이 그를 갈라놓는다.

### 세대교체 루프 (원작 오마주)

플레이어가 죽으면 **그의 아들(딸)이 20년 후 성의 문 앞에 다시 선다.**
세대마다 이름이 바뀌고(1세대: 카렌 → 2세대: 사이러스 → …), 성은 약간
변하지만 왕은 그대로이다. 플레이어는 몇 대를 거쳐 왕에게 도달할 것인가.
죽음은 게임오버가 아니라 서사의 한 페이지다 — 이 루프가 본작의 감정적
핵심이며, 랭킹 시스템("○세대 만에 정복")과 자연스럽게 연결된다.

### 3막 구조 + 보스 라인업 (에셋 매핑)

| 막 | 스테이지 | 보스 (원본 에셋) | 페이즈/개성 |
|---|---|---|---|
| 1막: 성문 | 1. 잿빛 문지기 | 그런트링 경비병 (Enemy_Gruntling) | 느린 2타, 튜토리얼 |
| | 2. 안뜰의 처형인 | 마스터 그런트 (Enemy_Master_Grunt) | 돌진+가드 강함 |
| 2막: 성 내부 | 3. 돌의 파수꾼 | 골렘 (Enemy_Golem) | 느리지만 한 방이 무거움, 가드 파괴 필수 |
| | 4. 거미 여왕 | 그레이트 스파이더 (Enemy_Great_Spider) | 빠른 연속기+위장 페이크 |
| 3막: 대장간 | 5. 서리의 기사 | 프로스트 자이언트 (Enemy_Frost_Giant) | 빙결 게이지(피격 시 회피 둔화) |
| | 6. 잉걸불의 왕 | 대장장이 왕 (Enemy_Forge_King) | 3페이즈: 검투→망치 난사→검과 망치 혼합 |

### 주요 대사 (프로토타입 스테이지 인트로 카드에 일부 수록)

- 1세대 주인공 카렌: "아버지가 말했다. 검은 기다린다고. 우리를."
- 대장장이 왕: "또 왔느냐. 아들의 얼굴은 아비를 닮았구나. 갈라놓기도 좋겠다."
- 불멸왕 아우사르(엔딩 티저): "네가 검을 쥘 때, 비로소 알 것이다.
  내가 왜 두려워했는지를."

### 엔딩 분기 (프로덕션)

- A. 검을 뽑는다 → 주인공이 새로운 불멸왕이 되고, 다음 세대가 **플레이어를**
  처치하러 온다 (루프의 완성).
- B. 검을 부순다 → 성이 무너지고 세대교체 루프 종료 — 진엔딩.

P1 파서 착수 시 주의: 단일 파일 패키지 특성상 FPackageFileSummary의
TotalHeaderSize 이후가 본문이며, 4.9 버전 프로퍼티 레이아웃을 따른다.

### P1 역공학 진행 상황 (2026-09-26, `tools/ue_mesh_extract4.py`)

확인된 사실 — 이 패키지는 재조립 도구로 uexp를 uasset에 통합한 **단일 파일
패키지**이며, 요약 헤더 일부 필드(Export/Import 테이블 위치)가 손상되어
표준 파서(umodel·FModel)는 그대로 못 쓴다. 그래서 휴리스틱 파서를 직접
작성하는 길을 택했다.

- 파일 구조: 페이로드는 `TotalHeaderSize`(0x18 슬롯, 예: 80751)부터 파일 끝
  직전 패키지 트레일러(`C1 83 2A 9E`)까지. 요약 필드 손상 여부와 무관하게
  이 구간이 모델 데이터다.
- 이름표: 표준 위치(예: 235)에 있고, **FName 해시 없음**(verUE4=482 <
  504) → `len+문자열` 연속 런으로 전역 스캔해 확정 가능. 실제 67개.
- 버전: verUE4=482 → 이름 해시 없음, 익스포트 SerialSize int32, 커스텀
  버전 배열 비어 있음(=SkeletalMesh 커스텀 버전 0, 즉 최구형 레이아웃).
- 직렬화 순서(UEViewer UnMesh4 대조 완료): [프로퍼티+None] →
  Bounds(FBox 25B) → Materials(포인터 배열) → RefSkeleton → LODModels
  (Sections → Indices(FMultisize) → ActiveBones → **Chunks(편집자 정점 —
  이 팩은 편집자 데이터가 살아있어 최고 품질 지오메트리 획득 가능**) →
  GPU 정점 버퍼).
- 남은 과제: RefSkeleton 직전 앵커가 예상과 달랐던 지점(파일 안에 FString
  "Root"가 별도로 존재 — 다른 익스포트 후작) 해소. 접근법: 편집자
  SoftVertices의 BulkSerialize 헤더(ElementSize,ArrayNum)를 페이로드에서
  역방향으로 스캔해 정점 버퍼를 먼저 찾고, 앞으로 RefSkeleton을 역파싱.
  이 방식이 시작 오프셋 추측에 가장 강하다.
- 도구: `tools/ue_package_inspect.py`(헤더/이름표 덤프, 동작),
  `tools/ue_mesh_extract4.py`(구조 검증형 브루트포스 — 앵커 문제 해소
  필요). 성공 시 OBJ+스켈레톤 JSON 출력 → Three.js 로더로 연결.
